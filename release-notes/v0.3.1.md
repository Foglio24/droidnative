## Fixes

- **Android did not start after a reboot** on PCs with an NVIDIA GPU and a second GPU (for
  example AMD or Intel integrated graphics). Linux numbers GPUs in the order their drivers
  load, and that order can change at every boot: waydroid-nvidia saves the NVIDIA GPU's number
  (`/dev/dri/renderD128` or `renderD129`) only when a mode is chosen, and its check at
  container start rejects a value left on the other GPU.
  - The new `droidnative-render-node.service` runs before every container start and, in venus
    mode, updates the node by finding the NVIDIA GPU by PCI vendor, then regenerates the
    container configuration. Nothing to do on your side.
  - If the container has already failed, Setup → “Start the container service” names the cause
    and repairs it with one click; the compatibility report and `droidnative session start`
    explain the problem instead of waiting for a timeout.
- The privileged helper ignored `--lang`: through pkexec its messages were always in English,
  even on an Italian system.

## Publishing

- CI publishes the release only after checking the uploaded package again, and retries the
  upload on transient GitHub errors (0.3.0 had stayed a draft because of one).

## Install

```bash
sudo apt install ./droidnative_0.3.1_amd64.deb
```

Run it in a terminal, in the folder where you downloaded the file. `SHA256SUMS` is attached;
provenance can be checked with
`gh attestation verify droidnative_0.3.1_amd64.deb --repo Foglio24/droidnative`.

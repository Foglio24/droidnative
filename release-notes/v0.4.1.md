## Fixes for GNOME with an NVIDIA GPU

- **The desktop glitched while an Android app was open** in *A window per app* mode: moving an
  Android window left trails of it over the whole screen, and Android's on-screen keyboard
  opened as a separate window that took the focus, so typed text seemed lost. With
  waydroid-nvidia this mode is tested on KDE (KWin) only: on other desktops DroidNative now
  disables it and explains why. If you had turned it on, choose *One window* on the Android
  apps page.
- **Direct subsurface turned off outside KDE.** `waydroid-nvidia-setup` turns
  `persist.waydroid.use_subsurface` on at every run; on GNOME that path can bring Android down
  (waydroid-nvidia issue #21: the display component aborts and SurfaceFlinger dies). DroidNative
  now turns it off after every waydroid-nvidia setup, mode switch or image switch, unless a KDE
  session is running. Android then composes its image on the NVIDIA GPU itself: acceleration
  stays. The compatibility report flags an existing install that still has it on, and Setup →
  “Set up the GPU backend” turns it off with one click.

## Good to know

- On GNOME the Android window has no title bar or borders, so it cannot be resized with the
  mouse: GNOME draws none for apps that do not draw their own, and Waydroid's display component
  does not. Running Android inside gamescope gives it a title bar, but Android then keeps a
  fixed resolution scaled into the window, so DroidNative does not do it.

## Install

```bash
sudo apt install ./droidnative_0.4.1_amd64.deb
```

Run it in a terminal, in the folder where you downloaded the file. `SHA256SUMS` is attached;
provenance can be checked with
`gh attestation verify droidnative_0.4.1_amd64.deb --repo Foglio24/droidnative`.
